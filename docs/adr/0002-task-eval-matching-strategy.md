# タスク抽出評価のマッチングは人手matchKey方式とし、deadline正確性は別指標にする

Issue #25のタスク抽出再現率・適合率評価（`backend/eval/run-eval.ts`）で、正解タスク（gold）とAI出力タスク（output）の対応付け（タスクマッチング）は、assigneeの一致と、goldタスクに人手で付与したmatchKey（名詞・動詞）がoutput.contentに含まれるかどうかで判定する方式を採用した。文言の完全一致はAIの言い換えで必ず取りこぼすため使えず、一方で埋め込みやLLMによる意味的マッチングは「評価は保存済み出力に対して行い、ライブAPI呼び出しに依存しない」「線引きの判断はAIに任せず本人が行う」という評価方針（issue #25背景）に反するため、人手でmatchKeyを付与する方式を選んだ。また、deadlineの一致・不一致はタスクマッチング成立の条件に含めず、マッチしたペアの中でのみ集計する「deadline正確率」として独立させた。タスクを発見できたかという失敗モードと、deadlineを正しく抽出できたかという失敗モードを同じ指標に混ぜないためである。

## Considered Options

- 文言の完全一致でマッチング → AIの言い換えで必ず不一致になるため却下
- 埋め込み/LLMによる意味的マッチング → 再現性が失われる（ライブAPI依存）ため却下
- deadlineの一致もマッチング成立条件に含める（厳密一致） → タスク発見の失敗とdeadline抽出の失敗が同じ指標に混ざり、誤り分析がしづらくなるため却下
